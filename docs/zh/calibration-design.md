# 真实数据校准设计(二期接入)

状态:**设计已备,未立项**——本页是 todo 条目「真实案例二期 + 模型校准」的仓内半边。条目本身仍 **BLOCKED** 于用户侧交付件(真实运营数据 + 对标基准);本设计的落地不解锁条目。替代红线:公开数值案例([宝可梦案例](./guide/21-pokemon-case.md) 等)永远不能替代真实运营数据——它们是结构参照,不是校准输入。

## 1. 校准在这里的含义

校准 = 为模型的**自由数值通道**选值,使仿真 KPI 输出在给定容差内复现观测到的真实 KPI。它**不是**模型扩张:不加新系统、不加新机制、不为没有真实侧观测量的东西发明 KPI(见[范围](./guide/02-scope.md))。

自由变量就是参数表的 `F64` / `U64` 数值槽位(默认 56 项,配 loot 后 57 项——见[随机函数](./guide/24-random-functions.md)配置面一节)。结构参数(权重表、公式、保底形态)保持手写;这让每个拟合值都可扫描、可经既有实验机制复跑。

## 2. 接入契约(解锁拟合的最小集)

真实侧数据以三份 CSV/YAML 交付件 + 一份可选项到达。列名固定,装载器只写一次;date 为日历日,cohort 索引为日粒度。

| 交付件 | 列(固定) | 校准(既有 KPI) |
| --- | --- | --- |
| `cohort_day.csv`(必需) | `date, cohort_day, cohort, retained_players, active_players` | `retention_d3`、`retention_d7`、`churn_rate` |
| `economy_day.csv`(必需) | `date, gold_granted_total, gold_spent_total, active_players` | `gold_per_player`;来源可拆时 loot 切片 → `loot_gold_per_player` |
| `meta.yaml`(必需) | population、观察窗口天数、cohort 份额、win 定义 + 若有则 `win_rate` 序列 | 锚定 `win_rate`;记录语义对齐(真实侧与仿真侧「什么算一次胜」) |
| `gacha_pulls.csv`(可选) | `account_id, pulls_to_first_hit` | `gacha_pulls_to_hit`(仅当真实案例有抽卡;合成案例已有闭式对账) |

**到件再定的开放映射**:`power_p50`(期末战力 p50)没有普适的真实侧观测量(战力是模型构造)。若真实游戏有成长代位指标(等级、关卡、战力),映射在接入时于 `meta.yaml` 固定;若没有,该锚点标 **unmapped** 并排除——绝不拿公开案例估算。

缺任一必需交付件 ⇒ 其锚点标 unmapped。缺件收窄拟合面;绝不被替代。

## 3. 拟合方法(只用既有件)

1. **冻结结构**——结构参数手写;自由集 = 拟合配置中记录的数值通道子集(带边界),使每一步都可仅凭 `sweep` / `optimize` 复现。
2. **粗网格**——对自由通道跑 `sandtable sweep`。候选目标函数:`Σᵢ wᵢ · ((sim_midᵢ − obsᵢ) / obsᵢ)²`,`sim_mid` 取 CI₉₅ 中点,`wᵢ = 1 / rel_varᵢ` 来自观测侧自身的置信区间(真实侧 CI 宽的锚自然权重低)。
3. **精修**——以网格最优点为种跑 `sandtable optimize`(约束感知进化;见[参数扫描](./guide/12-parameter-sweep.md));网格大时用随机森林 `surrogate` 筛。GP 维持否决(2026-10-10 决策:无线性代数依赖、确定性、可解释——本设计不改变它)。
4. **接受或如实报**——逐锚 `|sim_mid − obs| / obs ≤ 10%`(与 CI 平衡回归同带),retention 保持绝对底线 0.9(高留存的 −10% 下探会越过文档健康线——与 `cases.rs` 同理)。达不到的锚点带残差如实报未达标;不掰弯模型硬过。

确定性:固定 seed 集;同一拟合配置重跑产出逐位一致的拟合值([数据输出](./guide/09-data-output.md)的 CI₉₅ / hash 纪律不变适用)。

**过拟合防线**:按日窗口 hold-out——观察窗口前 ~70% 拟合、尾段判定。曲线形序列(留存衰减、经济累积)下尾段 hold-out 是最便宜有效的检查;不需要新机制。

## 4. 决策点(2026-10-19 巡检代决;记录亦见[方向项定义草案](./方向项定义草案.md) §4)

| 决策点 | 选择 | 理由(一句) | 被否 |
| --- | --- | --- | --- |
| 1. 自由变量 | 仅数值通道 | 拟合值保持可扫描,确定性叙事不破 | 拟合循环内自由改模型 |
| 2. 拟合机制 | 既有 `sweep` + `optimize` + RF 代理 | 零新依赖;与生产实验同管线 | GP 代理(2026-10-10 已否,不变);外部优化器 crate |
| 3. 目标函数 | KPI 中点上的加权相对残差 | 比率与金币差数量级;相对 + 观测 CI 权重中和量纲 | 绝对残差(金币压倒一切);全似然/贝叶斯拟合(接入件未必支撑分布假设——到数据再议) |
| 4. 验收带 | ±10% 相对 + retention 底线 0.9 + 尾段 hold-out | 与 CI 平衡纪律一致;见数据前不发明定制带 | 见数据前为逐锚发明定制容差 |
| 5. 缺交付件 | 锚点标 unmapped | 诚实优先于覆盖面 | 拿公开数值案例顶替(账本红线) |

## 5. 明确不在范围

无真实侧观测量的新 KPI、模型/系统扩张、Web API、版本号触发,以及用户保留的四类(版本号/发版、License、付费采购、素材授权)——这些都不是校准工作。

## 6. 触发

用户交出 §2 交付件时条目解锁。实施顺序:装载器(CSV → 观测表 + `meta.yaml` 解析)→ 拟合配置面(自由集 + 边界)→ 目标函数接入 sweep/optimize 评分 → 验收报告(逐锚残差表)。每步先补测试,按仓规。
