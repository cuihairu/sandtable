# 后续方向定义草案:CI 平衡回归与可视化系统图

**状态:定义草案,待拍板。** 两项在 `计划-原始.md` 即为裸名登记(无展开),docs/02 后续方向沿用。本文按 engine-adapter-design 先例(设计先行,拍板后实施)给出:现状盘点、缺口、方案选项与推荐、决策点。**拍板前不占用实现资源。**

## 1. CI 平衡回归

### 1.1 现状盘点(已覆盖面)

- **黄金快照**:默认配置指标逐字节 + `config_hash`(core 测试)——内核任何行为变化 CI 即红;
- **案例梯度**:`crates/sandtable-cli/tests/cases.rs` 宝可梦分层梯度(单调性 / 分层断言);
- **解析解对照**:保底期望抽数闭式对账(24 章);
- 以上全部跑在 CI `cargo test --workspace`。

结论:「内核行为变 → CI 变红」已覆盖;缺的是「**平衡水平**变 → CI 变红」。

### 1.2 缺口

案例数值(`examples/pokemon.yaml` 等)被改动时,KPI 绝对水平(churn_rate / retention_d7 / win_rate)的漂移没有 CI 断言,只有人工 review 兜底——黄金快照锚的是默认配置,不锚案例配置。

### 1.3 方案选项

| 方案 | 做法 | 代价 | 判断 |
| --- | --- | --- | --- |
| A. 维持现状 | 黄金快照 + 梯度测试,水平漂移靠 review | 零 | 可接受但兜底在人 |
| **B. 案例 KPI 水平断言(推荐)** | 对 pokemon.yaml 30 天基线加窄区间断言(churn_rate 区间、retention_d7 下限等,阈值取 docs 21 记录基线 ± 容差);改案例数值必须同时更新断言 | 一个测试文件增量,CI 时长不变 | 平衡漂移从人工兜底变 CI 拦截;成本最低的真缺口 |
| C. 独立 balance 回归 job | CI 跑全案例集出 KPI 报告对比基线文件 | 新 CI job,时长与维护成本高 | 收益边际,不推荐 |

### 1.4 决策点(待拍板)

1. 做不做(B 还是维持 A);
2. 阈值宽严(建议:docs 21 记录基线 ±10%,或统计 CI 外扩);
3. 是否顺带锚 gacha-pity 案例(E[T] 已有闭式对账,边际小)。

## 2. 可视化系统图与策划工作流

### 2.1 现状盘点

- 系统语义分散:kernel(04)/ 配置与公式(07)/ 扫描(12)/ 推荐(15)/ 案例(21);无单张全景图;
- 公式曲线已有**程序生成**先例:`formula_curves.rs` 对真实求值器采样出 SVG(docs 25)——文档与实现不漂移的既定纪律;
- 策划操作路径(改 YAML → simulate → sweep → recommend → report)分散在 10/12/15/21 各章,无一页导览。

### 2.2 缺口

- 新读者无一页看懂「仿真环里有哪些 System、数据怎么流」;
- 「我要改一个数值并验证影响」要跨四章自己拼路径。

### 2.3 方案选项

| 方案 | 做法 | 代价 | 判断 |
| --- | --- | --- | --- |
| **A. 系统图程序生成(推荐)** | core 加 example(如 `system_graph.rs`)按 System 注册表实况输出图(订阅事件 / 数据流)→ SVG 落 `docs/assets/`,04 章引用 | 一个 example;手绘必漂移,程序生成同 formula_curves 纪律 | 推荐 |
| **B. 策划工作流一页(推荐)** | 「从改数到验证」五步导览,不开新章,并入现有章(02 或 21),链接既有章节 | 半页文档 | 推荐 |
| C. 交互式系统图 | Web 端画 system graph | 前端开发量 | 按需,现在不做 |

### 2.4 决策点(待拍板)

1. 图生成方式(程序生成 vs 手绘 SVG);
2. 图信息密度(仅 System 名 + 订阅事件 / 含数据流箭头);
3. 策划工作流落点(02 / 21 / 新 26 章)。

## 3. 拍板后的动作

- §1 拍 B:先补测试(阈值断言,落点 cli/tests/ 与 cases.rs 同文件)→ `cargo test -p sandtable-cli` 绿 → 落地;
- §2 拍 A+B:example 出图 → 章节接线 → `pnpm docs:build` 绿 → 落地。
