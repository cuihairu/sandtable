# Sandtable 专业工作台功能蓝图

> 状态：产品方向草案，待后续按优先级拆解与实现。本文描述面向游戏数值策划的桌面工作流，以及与成熟商业软件的集成边界；不代表下列功能已经实现。

## 1. 产品目标

Sandtable 应成为数值策划的实验工作台：策划能管理基线和候选方案、编辑参数、设计并运行实验、解释结果、保存结论并复现分析。产品核心对象是一次完整实验，而不是单独的 YAML 文件或图表。

目标工作流：

```text
打开项目 → 选择游戏版本与基线 → 编辑参数 → 创建候选方案
→ 检查变更与影响 → 设计实验 → 运行仿真
→ 分析差异与不确定性 → 记录结论 → 导出或分享
```

产品定位继续遵守 Sandtable 的现有原则：仿真用于相对比较和平衡探索；结果需要结合模型假设解释，不应呈现为对真实玩家行为的绝对预测。

## 2. 信息架构

建议桌面工作区采用左侧项目导航、中央工作区、右侧上下文检查/运行状态的结构。一级模块：

```text
项目
├── 场景与基线
├── 参数库
├── 实验
├── 结果分析
├── 报告
└── 数据连接与导出
```

全局栏显示项目名、游戏/平衡版本、配置版本、保存状态和当前运行状态。运行任务应在页面切换时持续可见。

## 3. 功能范围

### 3.1 项目与工作区

- 创建、打开、复制和归档项目；复制时允许选择仅复制配置，或连同实验、结果一起复制。
- 项目包含场景、基线配置、候选方案、实验记录、结果、报告、KPI 定义和图表模板。
- 选择游戏版本、平衡版本或配置分支；查看当前配置来源和版本。
- 每次运行保存不可变的输入快照，避免配置后续变化覆盖历史实验。
- 记录配置哈希、仿真模型版本、随机种子、玩家规模、运行天数、replicates、指标定义版本、软件版本和运行时间。
- 如启用团队协作，追加创建者、修改者、审核人及权限记录。

### 3.2 场景与基线

- 创建可复用场景，如新手期、日常玩法、后期养成、不同活动环境或不同玩家结构。
- 场景保存基线引用、行为模型、玩家 cohort 配比、仿真周期、玩家规模和默认关注 KPI。
- 支持多个基线版本；明确显示当前候选方案从哪个基线派生。
- 基线设为只读或需显式解锁，避免策划误将试验改动写入基线。

### 3.3 参数库与参数编辑器

#### 参数组织与查询

- 按战斗、成长、经济、掉落、抽卡等系统分组，并允许按对象、阶段和标签继续组织。
- 按名称、稳定 ID、所属系统、说明、标签及数值范围搜索。
- 收藏常用参数；筛选最近修改、当前方案变更、实验扫描参数。
- 展示配置文件及路径，支持从参数定位到高级配置文本。

#### 参数元信息

每个参数应具备名称、稳定 ID、系统归属、当前值、数据类型、单位、默认值、上下界、步长、说明、设计意图、适用对象、作用阶段、依赖关系、影响 KPI、配置来源和是否允许覆盖等信息。

#### 类型化编辑

- 整数/浮点数：数值框、步长调整、范围限制和单位显示。
- 概率：百分比输入，清楚区分显示值与底层比例。
- 区间、成长曲线：曲线编辑器、表格编辑和公式编辑入口。
- 掉落表/加权表：表格编辑、权重合计检查和期望值预览。
- 阶段规则：结构化条件/动作编辑，明确触发条件和状态转移。
- 公式：语法高亮、函数提示、语法检查、样例求值和错误定位。
- 保留 YAML 等高级入口，适合工程师和熟悉配置的策划；结构化编辑与文本编辑应相互同步。

#### 变更与校验

- 与基线并排比较；标记新增、删除和修改项，显示绝对差值与百分比变化。
- 支持撤销、重做、单项恢复、批量倍率/偏移和命名方案。
- 每次改动可写备注，如“降低前期卡关率”。
- 运行前检查类型、范围、单位、缺失引用、重复 ID、公式、概率/权重合计、曲线形状和明显的资源产消异常。
- 检查结果分为错误、警告、提示，并能跳转至对应参数。
- 展示可能受影响的系统和 KPI；影响关系无法确定时标为未知，不制造确定性。

### 3.4 候选方案管理

- 从基线创建候选方案；每个方案有名称、目的、说明、参数差异、场景、创建时间和最近运行状态。
- 支持一个基线对比多个候选方案、两个历史版本比较和扫描点比较。
- 运行前呈现配置差异摘要，确保结果能够对应到明确的改动。
- 可复制方案、合并已选改动，或将验证后的候选方案晋升为新基线（需明确操作并保留旧版）。

### 3.5 实验设计器

#### A/B 对比

- 选择对照方案、一个或多个候选方案、观察指标、仿真天数、玩家规模、replicates、seed 策略、cohort 和输出粒度。
- 配对实验解释两边共享随机键的意义；呈现每组条件和统计单位。
- 运行前给出任务摘要、组合数量、估计耗时和预期产物。

#### 参数扫描

- 支持单参数区间扫描、多参数网格、随机采样、拉丁超立方和离散候选值。
- 设置每个参数的边界、步长或候选集合。
- 执行前预览组合数和计算量；可按资源预算限制扫描规模。
- 支持暂停/取消、失败点重跑、结果排序、筛选和标注。

#### 敏感性分析

- 指定目标 KPI、分析参数、变化范围和方法。
- 显示影响方向、幅度、参数排序、适用范围与限制。
- 允许从分析结果直接建立后续扫描或候选方案。

#### 优化与约束

- 定义优化目标和 KPI 上下限；可设置多个目标并查看 Pareto 权衡。
- 清楚展示搜索范围、约束条件、使用的方法、已评估组合数和停止原因。
- 推荐结果须能回到对应配置和实验，不输出无法复现的孤立建议。

### 3.6 运行管理

- 运行前完成配置/实验校验，显示组合数、估计耗时和输出大小。
- 运行中显示阶段、已完成/总 replicates、候选进度、错误和警告。
- 支持取消任务；取消粒度和已完成结果保留策略应在界面说明。
- 任务在后台运行，页面切换时进度仍可查看；完成后提供通知。
- 运行结束后生成不可变记录，可查看、复制设置、重跑、导出或标记失败原因。

### 3.7 结果分析与图表

#### 结果总览

- 每个 KPI 呈现基线值、候选值、绝对差、相对变化、置信区间、效应量和判定状态。
- 展示样本规模、replicates 和统计单位；区分“未达到目标”和“证据不足”。
- 结果摘要说明变化较大的指标及其条件，但不自动把相关性表述成因果机制。

#### 图表类型

- 时间序列：基线/候选叠加、差值曲线、置信区间带。
- 分布图：直方图、箱线图、分位数带，用于识别长尾及人群差异。
- cohort 对比：按 Casual/Core/Whale 等群体分面或筛选。
- 参数扫描热图：展示两个参数组合与 KPI 的响应面。
- 敏感性图：显示参数影响方向和相对幅度。
- Pareto 图：显示多目标权衡和可选方案。
- 经济流图：产出、消耗、存量和回收变化。
- 抽卡/掉落图：期望抽数、概率分布、保底前后结果。

#### 图表交互和解释信息

- 图例开关、cohort/日期/方案筛选、缩放、重置和精确值悬停。
- 标注参数变化点；从图上选择结果点查看对应方案和实验条件。
- 导出 PNG、SVG、CSV，或复制到报告。
- 每张图能查看指标定义、统计口径、样本量、replicates 和模型假设。
- 默认展示适合阅读的聚合结果；原始明细按需加载，避免一次绘制大量点造成卡顿。

### 3.8 实验历史与结论

- 按名称、日期、场景、参数、KPI、标签和负责人搜索历史实验。
- 实验记录可写目标/假设、预期方向、结果、策划结论、采纳状态和后续验证事项。
- 可比较历史实验条件，区分参数变更和运行设置变更。
- 支持标签、收藏、复制实验和生成复跑任务。

### 3.9 报告

- 一键生成 HTML/PDF 报告及机器可读数据。
- 报告包含实验目的、方案差异、运行条件、指标结果、图表、统计信息、模型假设和结论备注。
- 支持报告模板、图表选择和团队标识；导出结果保留配置/实验标识以便追溯。

### 3.10 团队协作（后续阶段）

- 共享项目、角色权限、只读链接和编辑权限。
- 评论、审核状态、变更锁定、冲突提示和审批记录。
- 记录实验负责人、审核人及方案采纳状态。
- 多人协作依赖服务端能力，不纳入 local-first 桌面版第一阶段的前置条件。

## 4. 商业软件与外部工具集成

集成分为三层，先保证文件互通，再考虑启动外部程序，最后才开发服务/API 深度集成。Sandtable 不应要求用户购买 MATLAB 或 BI 软件才能完成核心仿真和分析。

### 4.1 Excel（第一优先）

- 提供参数导入模板和字段字典。
- 支持 XLSX/CSV 导入预览、列映射、类型转换、单位校验和错误报告。
- 导入前展示差异；由用户确认后写入候选方案，不直接覆盖基线。
- 导出参数表、变更表、逐日 KPI、cohort 汇总、扫描结果和实验摘要。
- 生成适合 Excel 筛选/透视分析的扁平表，并附实验 ID、配置哈希和指标定义版本。
- 后续可提供“在 Excel 中打开”快捷操作；首版不要求开发 Excel 插件。

### 4.2 Power BI / Tableau（第二优先）

- 提供稳定的数据包和字段字典，建议按用途拆分：`runs`、`metrics_daily`、`cohorts`、`parameters`、`parameter_changes`。
- 支持 CSV、JSON、Parquet 等结构化导出，明确 schema 版本和单位。
- 目标是让团队在 Power BI/Tableau 中做跨项目、跨版本的长期汇总；Sandtable 本身仍负责单次实验的专业分析。
- 先做文件级互通；发布到 Power BI Service、Tableau Server/Cloud 和自动刷新属于后续企业集成。
- Power Query 对 CSV 和 JSON 有官方连接器；不同宿主和平台支持存在差异，应以 CSV 作为基础交换路径。[Microsoft Power Query 数据源](https://learn.microsoft.com/en-us/power-query/where-to-get-data) · [CSV](https://learn.microsoft.com/en-us/power-query/connectors/text-csv) · [JSON](https://learn.microsoft.com/en-us/power-query/connectors/json)

### 4.3 MATLAB（可选高级集成）

- 首版：导出 CSV/JSON/Parquet，并提供 MATLAB 脚本模板，加载实验数据、选择列和生成基础分析图。
- 中期：增加“生成并运行脚本”能力，结果和日志写回独立目录，不篡改原始实验结果。
- 后续按实际需求评估本机 MATLAB Engine 连接器。MathWorks 提供 MATLAB Engine API for Python，可由 Python 调用已安装的 MATLAB；此方案要求用户本机安装 MATLAB 和兼容环境，因此必须是可选连接器，不能成为 Sandtable 基础运行依赖。[MathWorks MATLAB Engine API for Python](https://www.mathworks.com/help/matlab/matlab-engine-for-python.html)
- 不把 MATLAB 界面嵌入 Sandtable，也不把 MATLAB 作为 Sandtable 默认图表渲染器。

### 4.4 Python 与自动化（可选扩展）

- 提供稳定的项目/实验/结果 schema 和 Python SDK。
- 支持脚本创建实验、批量运行、读取结果和生成自定义分析。
- Python 扩展失败应与核心仿真隔离；记录脚本、依赖和输入版本以便复现。

## 5. 分阶段路线

### Phase A：策划闭环

- [ ] 项目、场景和基线的基础管理。
- [ ] 参数按系统浏览，查看说明、单位、范围和来源。
- [ ] 类型化参数编辑、变更对比、撤销和配置校验。
- [ ] 基线/候选方案管理。
- [ ] A/B 实验设计与运行状态。
- [ ] KPI 差值、置信区间、效应量和基础时间序列/分布图。
- [ ] 不可变实验记录、复跑和 HTML 报告。
- [ ] CSV 参数导入导出、结果数据导出。

### Phase B：实验分析效率

- [ ] 网格/随机/LHS 扫描设计器。
- [ ] 参数扫描热图、敏感性分析和 Pareto 展示。
- [ ] cohort 与分布分析增强。
- [ ] Excel 模板、XLSX 导入预览和字段映射。
- [ ] 自定义 KPI、图表模板和报告模板。
- [ ] 批量任务队列、失败点重跑和结果筛选。

### Phase C：外部生态与团队能力

- [ ] Power BI/Tableau 数据包、字段字典和示例模型。
- [ ] MATLAB 脚本模板与可选本机调用评估。
- [ ] Python 自动化 SDK 与自定义分析扩展。
- [ ] 共享项目、权限、评论、审核和冲突处理（需要服务端决策）。
- [ ] 企业数据源和 BI 服务端发布（根据真实用户需求评估）。

## 6. 设计与实现约束

- 核心仿真、统计口径与配置 schema 不依赖商业分析软件。
- 所有导入操作先预览、校验和展示差异；不静默覆盖基线或历史结果。
- 实验结果必须保存足够元数据，确保能追溯和复跑。
- 图表优先消费聚合结果；常规图先用 SVG，密集数据经实测后再对特定视图使用 Canvas。
- 长任务放在桌面后台/WASM Worker 等非界面线程，通过事件推送进度。
- 外部集成器可缺席或不可用，不能影响项目文件读取和核心仿真。
- 商业软件授权、软件版本和平台差异应由可选连接器处理，并在连接状态中明确展示。

## 7. 当前基础与后续差距

当前仓库已有 CLI、Web(Rust/WASM + React)、Tauri 桌面壳、配置编辑、实验/扫描、基础图表、CSV/Parquet 和 HTML 报告能力。本文提出的项目工作区、结构化参数元信息与编辑器、候选方案/实验历史、策划结论记录、Excel 工作流和专业报告体验，仍需逐项对照现有实现并拆分需求。产品信息架构与统计交互约束见 [`docs/专业工作台界面设计.md`](专业工作台界面设计.md)。V2 可交互原型源码位于 `apps/web/public/prototype/`，启动 Web dev server 后访问 `/prototype/index.html`；包含分析、参数、实验、任务和数据五个工作区，使用合成样例，不连接仿真内核。具体排期以 `todo.md` 中的功能待办为准。
